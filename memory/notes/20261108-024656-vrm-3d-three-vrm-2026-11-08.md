2026-11-08 在电脑上跑通了 **VRM 3D 模型的无头渲染**，5 秒样片验证通过。

## 产物与环境
- 样片：电脑 `~/live2d/poc3d.mp4` / 手机 `/sdcard/Download/live2d-poc3d.mp4`（5.000s / 1080×1920 / 25fps / 125 帧 / 1.2MB，md5 一致）
- 脚本：`~/live2d/poc3d/index.html`（场景/表情/时间轴）+ `~/live2d/poc3d/render.js`（puppeteer 驱动，`node render.js --out <dir> [--probe] [--limit N]`）
- 版本：`three@0.169.0` + `@pixiv/three-vrm@3.5.5` + `puppeteer-core@21.11.0`（three-vrm 的 peerDep 只写 `>=0.137`，0.169 实测正常）
- 取帧仍是 `canvas.toDataURL()` + `preserveDrawingBuffer`；headless Chrome 要 `--enable-unsafe-swiftshader --use-gl=angle --use-angle=swiftshader`

## 模型与许可
- `AvatarSample_A.vrm`（15MB，**VRM 0.0**），来自 `madjin/vrm-samples` 的 `vroid/stable/`，是 VRoid 官方 sample
- 许可证是 **VRoid AvatarSample 系列条款**（可自由使用/修改/分发、允许商用），**不是 CC0**，条件页 https://vroid.pixiv.help/hc/en-us/articles/4402394424089
- 表情名（three-vrm v0compat 映射后）：`neutral, aa, ih, ou, ee, oh, blink, blinkLeft, blinkRight, angry, relaxed, happy, sad, Surprised, Extra`

## 三个坑
1. **VRM 0.x 的 `E` 被 three-vrm 映射成 `ee` 而不是 `eh`**。写错名字只 `console.warn` 然后静默不生效（嘴部 diff 只有 0.3 就是这个原因）。
2. **静态 T-pose 手臂会横穿竖屏头肩构图**，要手动转 `leftUpperArm` / `rightUpperArm` 的 normalized bone（`rotation.z ∓1.05`）。
3. **MToon 材质极吃光**：DirectionalLight 2.4 + Ambient 2.0 直接把脸打成纯白；降到 Ambient 0.38 / key 0.62 / fill 0.28 / rim 0.22 才正常。

## 性能与缺口
渲染 **1.22 秒/帧**（1080×1920 PNG base64 往返是瓶颈；Live2D 那套 250 帧 23 秒不可直接类比，它裁切框很小）。
接进正式流程还缺四样：① 换 `readPixels` 直传像素，把速度压到 0.2 s/帧量级；② 口型接 TTS 音素时间轴（现在是伪随机音节表）；③ 身体动作/手势（现在只有头部摆动）；④ 开 alpha 通道 + 换成鲸鲸自己的 VRM。
