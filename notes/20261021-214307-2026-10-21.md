主人 2026-10-21 定的长期规矩：**遇到任何需求，先去 B 站 / GitHub 找现成方案，不要一直造车轮子**。他原话：「以后遇到什么东西都可以先找一找，不要一直造车轮子」。

执行顺序：B 站搜教程/视频 → GitHub 搜项目 → 再考虑自己写。

## 本次的实例（值得记住的结论）
想让手机上「息屏时也能自动化操作 App」，不需要自己写无障碍桥。GitHub 上已有三个项目，核心都是 **VirtualDisplay 虚拟显示器 + Shizuku 授权**：
- `kuomartin/moonclicker` —— Lua 脚本 + Shizuku 虚拟显示 + 触摸注入 + 板载模板匹配/OCR（类 MAA）
- `hakai963/headless-android` —— Shizuku 无头虚拟显示引擎：启动 App、实时预览、输入注入
- `android-notes/ShadowAuto` —— 在虚拟显示上跑 App，用模型工具调用控制（与 DSH 组合最接近）

原理：VirtualDisplay 不依赖物理屏幕，App 渲染到虚拟屏上，所以**物理屏熄灭也能截图/操作**——这才是「息屏挂机」的通用实现。物理屏截图在息屏时必黑（screencap 拿不到画面），任何人都一样（MAA 也一样）。

## 本机现状（2026-10-21）
- DSH 已在电池优化白名单，`RUN_ANY_IN_BACKGROUND: allow`，息屏后 Node 引擎照跑（跑任务可以，看屏幕不行）
- Shizuku 通道曾可用（`dsh-android-shell.mjs` 支持），当时显示「Shizuku 服务未运行」回落到 legacy adb 5555
- 分享接收已打通：HTTP Shortcuts 快捷方式 send → POST 127.0.0.1:8899 → `~/.dsh/share-inbox/inbox/`（插件 `dsh-share-inbox` + patch，需 App 重启验证自动加载）
