陈 2026-11-14 02:00 定的两条（睡前提的）：

## 1. 记忆自动落盘：每 12 小时或重大更新后写一次
起因：陈原话「以后做一个脚本任务吧，每 12 小时自动写入一次，或者重大更新写入一次，不然容易失忆」。
已落地：定时任务 `schedule-2d13564f-94a4-4a1c-9b87-8dbb39e925f1`（RRULE:FREQ=HOURLY;INTERVAL=12，首次 2026-11-14 14:00 Asia/Shanghai，target=new_once）。每次动作：读 handoff → 只在有实质变化时改写 → memory_write → rsync 电脑 + push GitHub `jingjing-memory` → 回一段汇报。没有实质变化就报「无变化」，不为了写而写。

## 2. remote 要优化，别双份烧 token
陈原话：「你给开心对话，和他对话，但是我的 token 会烧得比较快，是双份的」「你想想办法，优化一下连接吧」。
已落地**零 token 链路**（电脑当执行器，不调模型）：
- 手机 `~/dsh-link.sh task '<命令>'` → 写 `~/.dsh/link/out/*.sh` → rsync 到电脑 `~/.dsh/link/in/`
- 电脑 `~/.dsh/link/runner.sh`（cron `*/2 * * * *`）纯 shell 执行 → 结果写 `~/.dsh/link/out/*.result`，任务移 `done/`
- 手机 `~/dsh-link.sh pull` 收结果
- 实测往返 ~30 秒：发 `hostname; uptime; nvidia-smi` 收回 `cyx-GI5CN54 / load / 145 MiB`
- 原则：**默认不起第二个模型**；确实要电脑动脑时，才用便宜模型（agnes）跑一次 headless，而且只跑有任务的，不常驻。

（连通的三个断点仍待处理：电脑 DSH 只监听 127.0.0.1:3080、jiuling-remote/ds-harness-remote 两边未建连、memory-sync peer :18792 未开。上面这条链路绕开了它们，用 SSH + 本地文件。）
