## 来源与性质
2026-11-03 凌晨，陈发了三张豆包/DeepSeek App 的截图（对话标题「鲸鲸交接口吻」），内容是"如何为鲸鲸配置模型团队"。
**这些插件名是外部 AI 说的，还没核实是否真的存在于 DSH 插件市场，名字可能有误。**

## 截图里提到的插件与用途

1. **dsh-ai-roundtable（圆桌会议）**
   - 首轮各模型独立作答、互不可见，由中立调度员决定发言顺序
   - 只摊开角度和分歧，适合多角度脑暴
   - 还可做「挑刺者 Red Teaming」：配一个专门唱反调的模型（如 Kimi），强制找方案漏洞，打破逻辑上的自我强化

2. **dsh-work-chain（工作链）**
   - 当前会话当 Leader，配置多个不同框架/模型的成员并行干活
   - 适合并行调研、多视角代码审查，Leader 汇总
   - 用法：鲸鲸当"项目经理"，Kimi/Qwen 当"专项专家"。遇到报错，把日志发给 Kimi 分析，拿结论再执行。每个模型在自己干净的上下文里工作

3. **dsh-council（团队）** —— 与 work-chain 同一类

4. **dsh-agent-teams（上下文隔离）**
   - 每执行几个步骤就强制结束当前 Agent，生成一份类似 HANDBOOK.md 的交接报告，
     再唤醒一个全新 Agent 拿着报告继续干；永不让它在快撑爆的上下文里强行思考

5. **dsh-native-collab（原生协作）**
   - 基于 DSH 原生模块，按宿主允许的模型列表选择，无缝接入

6. **dsh-loop-guard（硬熔断）**
   - 两个模型互相复读，或同一个坑连报三次相同错 → 插件强行掐断当前回合
   - ⚠️ 注意区分：我们 AGENTS.md 里自建的 `dsh-loopguard` 段落是一段**规矩**，不是插件

## 接入第三方模型（截图说法）
在 `~/.dsh/settings.yaml` 里配置第三方模型路由（需要 API Key）即可接入 Kimi / GLM / Qwen。
子代理默认继承父会话模型，需要配合插件才能换模型。
