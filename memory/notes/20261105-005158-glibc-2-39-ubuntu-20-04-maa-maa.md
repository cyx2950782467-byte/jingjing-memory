## 用 glibc 嫁接法让 Ubuntu 20.04 跑 MAA（2026-11-05 成功）

陈要求"在电脑上装明日方舟自动化，之后让我帮他玩舟"。MAA 官方包要求 **glibc 2.39**（Ubuntu 24.04 级别），而机器是 **20.04（glibc 2.31）**。**用 glibc 嫁接法绕过去了**。

### 做法（三步，不用改系统）

```bash
# 1) 下 Ubuntu 24.04 的 libc6（清华源，3.2MB）
cd /tmp
curl -sL -o libc6_239.deb "https://mirrors.tuna.tsinghua.edu.cn/ubuntu/pool/main/g/glibc/libc6_2.39-0ubuntu8_amd64.deb"
dpkg-deb -x libc6_239.deb /tmp/glibc239

# 2) 解包后的真实路径是 usr/lib/x86_64-linux-gnu/（不是 lib/x86_64-linux-gnu/）
G=/tmp/glibc239/usr/lib/x86_64-linux-gnu

# 3) 用新 ld-linux 直接引导，不碰系统库
cd /mnt/m2/maa
$G/ld-linux-x86-64.so.2 --library-path "$G:/mnt/m2/maa" ./maa --version
# 输出：maa 0.7.8  ✓
```

已封装成 `/mnt/m2/maa/run-maa.sh`（所有命令走它）和 `setup-glibc.sh`（一次性解包）。

### 关键验证
- 报错是 `libc.so.6: version GLIBC_2.32/2.33/2.34 not found`
- `objdump -T ./maa | grep -oE "GLIBC_2\.[0-9]+"` 一查就知道真实要求（**2.39**，不是 2.32）
- 22.04 的 2.35 **也不够**，必须 24.04 的 2.39

### 为什么官方说"不支持 Linux"
文档原文：「MAA GUI **暂未支持** Linux」。但**发出来的 linux 包里的 `maa` 是 maa-cli 0.7.8**，能跑，命令齐全（startup/fight/copilot/roguelike/closedown/install/update）。

### 还差什么
**连设备**。maa-cli 要 ADB 连模拟器或真机：
- 手机端 Shizuku 没跑、无线调试没开（需要陈在手机上开一次）
- 电脑端 adb 已装（`android-tools-adb` 1.0.39）
- 模拟器：Waydroid 需要 Wayland + ARM 转译（舟是 ARM 游戏），不乐观

### 通用价值
**这个嫁接法能救所有"新编译二进制 + 老系统"的组合**（PZ 的 GLIBCXX 3.4.29 也能这么搞，不用等升系统）。
