2026-11-18 凌晨在电脑（机械革命 GI5CN54，Ubuntu 24.04.5 / 6.8.0-149）上做的两件事，结论自包含：

## 一、DSH 网页 303→400 的根因（已修）

**根因**：第三方插件 `dsh-lan-web-access@0.1.9` 的 `guard.js` 把 DSH webServer 的 fallback 当**函数**调用，但 DSH 0.2.2-rc.1 的 fallback 是 **`{ resource }` 对象**。类型不匹配抛 `TypeError: handler is not a function`，被 `dsh-host-webserver/lib/index.js` 的全局兜底 catch 吃成**裸 400**（`res.writeHead(400)`，无 body 无额外头），所以每个前端路由（连 `/does-not-exist`）都 400，而 `/api`、`/connect` 正常 —— 这个「只有 fallback 路径 400」是识别该 bug 的判据。

**定位方法**（下次遇到类似问题照做）：在 host-webserver 的 catch 里临时插 `console.error(err.stack)`，重启用户服务 `systemctl --user restart dsh-web`（不是 reboot），抓堆栈，再还原。日志 `~/.dsh/dsh-web.log` 里没有 logger.warn 输出，所以必须插探针。

**修法**：给 `~/.dsh/profiles/web/node_modules/dsh-lan-web-access/lib/guard.js` 的 `guardFallback` 开头加两行 `if (typeof handler !== 'function') return handler;`。备份在 `/home/cyx/lan-guard.js.bak-0.1.9`。**上游 0.1.10 已修**，将来升级插件后本地补丁会丢，删掉即可。

**验证**：token 入口 303 → 带 cookie `HTTP 200 bytes=540077`；错误 cookie 401。

**顺带**：cookie 名 = `dsh-auth-` + base64url(sha256(authority))，HTTP 下 authority 是 `url.host`（如 `127.0.0.1:3080`）；签名 secret 持久化在 credentials 的 `AUTH_RECORD_KEY`（kind=grant，32字节），重启不失效，cookie 活 30 天。浏览器用法：开 `http://127.0.0.1:3080/?token=<grep "dsh web:" ~/.dsh/dsh-web.log | tail -1 里的那串>`，成功后 30 天内直接开 `/` 即可。

**额外发现（未修，需陈决定）**：dsh-web 只绑 `--host 127.0.0.1`，局域网 `192.168.31.29:3080` 根本连不上（code 000）。`--trusted-host` 写了也没用。要局域网访问得改 unit 成 `--host 0.0.0.0`，但会把 UI 暴露到局域网。

## 二、显卡：还差一次开机确认

GTX 1050 Ti Mobile (GP107M, PCI 01:00.0)。驱动 `nvidia-driver-580 580.178.04` 已装，DKMS 已为 6.8.0-149 构建 5 个模块（nvidia.ko.zst 82MB），**已用本机密钥签名**（`/var/lib/shim-signed/mok/MOK.der`，CN=cyx-GI5CN54…）。但 SecureBoot enabled 且该证书 **not enrolled** → `modprobe nvidia` = `Key was rejected by service`。

**已做**：`mokutil --import` 把证书放进待注册队列（SHA1 36:df:ee:a3:61:64:88:25:69:21:5c:0a:1b:34:0b:0f:0e:54:c6:ca），**密码 `DshMok2026`**。

**必须人做**（完整步骤在电脑 `/home/cyx/MOK-注册步骤.md`）：下次开机蓝底 `Perform MOK management` 界面 → Enroll MOK → Continue → Yes → 输 `DshMok2026` → Reboot。或者 BIOS（F2）关 Secure Boot。两条路之后都不用再确认。

## 三、稳定性要点

- **发现硬件看门狗不存在**：`/etc/systemd/system.conf.d/watchdog.conf` 配了 `RuntimeWatchdogSec=30`，但**没有 `/dev/watchdog`**、没有 wdt 模块 —— 这条配置是空转的。**别去 modprobe iTCO_wdt**：systemd 没接管时硬件看门狗超时会直接硬重启这台机器。
- 新增 `/etc/sysctl.d/99-stability.conf`：`vm.swappiness=20`（原 60）、`vm.vfs_cache_pressure=80`，已 `sysctl --system` 立即生效。`kernel.panic=10` 保持，`panic_on_oops` **故意留 0**（内存坏导致的 oops 不该触发连环重启）。
- 备份：`/home/cyx/backup/dsh-config-2026-11-18.tgz`（11MB，369 文件，含 memory/storages/sessions/profiles 清单/AGENTS/handoff/publish-log/credentials）。`~/.dsh` 总量 2.1G 但 profiles 占 1.6G，所以排除后只有 11M。
- linger=yes、dsh-web enabled、heal.timer active、dsh-tunnel active 全部正常。
- 本轮 `journalctl -k` 0 条 mce/page fault。
