## 背景
2026-11-05 晚，陈把 `prime-select` 从 on-demand 切到 nvidia（独显主控桌面变快），之后 Project Zomboid 从 Steam 点开始游戏 4 秒就退出、无窗口、游戏日志 console.txt 不更新。on-demand 模式下游戏一直正常。

## 根因（两个坑叠在一起）
1. **DXVK 版本太新**：`proton_hotfix` 自带 DXVK 3.1.1，要求 `VK_KHR_load_store_op_none`；NVIDIA 535.230.02 只有 `VK_EXT_load_store_op_none`（老 EXT 版，不是 KHR）。日志表现：
   `Found device: NVIDIA GeForce GTX 1050 Ti` → `Skipping: Device does not support required feature 'khrLoadStoreOpNone'` → `Failed to initialize DXVK`。
2. **Steam 把兼容工具重置成 `legacysteamruntime`**：此时 Steam 直接跑 Linux 原生版 `./ProjectZomboid64`，在 Ubuntu 20.04 上必然报 `GLIBCXX_3.4.29 not found`。表现是 Steam 日志出现 `LegacySteamRuntime ... Using local scout runtime`。

## 修复（已验证成功，游戏能进）
1. **把 DXVK 降到 Proton 9 自带的 2.5.1**（不用下载）：
   ```bash
   B=~/.steam/debian-installation/steamapps/common
   cp -a "$B/Proton Hotfix/files/lib/wine/dxvk" "$B/Proton Hotfix/files/lib/wine/dxvk.bak-20261105"
   cp -f "$B/Proton 9.0 (Beta)/files/lib64/wine/dxvk/"{d3d11,dxgi,d3d10core,d3d9,d3d8}.dll "$B/Proton Hotfix/files/lib/wine/dxvk/x86_64-windows/"
   ```
   注意路径：Proton Hotfix 的是 `files/lib/wine/dxvk/x86_64-windows/`（分架构子目录），Proton 9 的是 `files/lib64/wine/dxvk/`（平铺）。
2. **把 CompatToolMapping 的 108600 改回 `proton_hotfix`**（`~/.steam/debian-installation/config/config.vdf`，必须 Steam 关着改）。
3. 前提条件（当晚也改过，留着）：`/usr/share/vulkan/icd.d/nvidia_icd.json` 的 `library_path` 改成绝对路径 `/usr/lib/x86_64-linux-gnu/libGLX_nvidia.so.0`（原备份 `.bak`）——不改的话 Steam Runtime 容器里的 DXVK 连 1050Ti 都看不见。
4. Steam 界面黑屏转圈：必须 `steam -cef-disable-gpu`，已写进 `~/.local/share/applications/steam.desktop`。

## 以后要注意（会复发）
- **Steam 更新 Proton 会把 DXVK 覆盖回 3.x** → 游戏又打不开，重新执行第 1 步即可。
- **Steam 可能再次把 CompatToolMapping 重置成 `legacysteamruntime`** → 检查 config.vdf，改回 `proton_hotfix`。
- 排查顺序：先看 `~/steam-108600.log`（`PROTON_LOG=1` 产生）里有没有 `Found device` 和 `Skipping ... khrLoadStoreOpNone`；再看 console-linux.txt 里是 `.exe`（Proton）还是 `./ProjectZomboid64`（原生版）。
- 存档在 `.../compatdata/108600/pfx/drive_c/users/steamuser/Zomboid/Saves`（58M），Proton 换版本重建前缀不会删它。
