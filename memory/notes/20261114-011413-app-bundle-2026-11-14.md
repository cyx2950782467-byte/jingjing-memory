2026-11-14 凌晨 00:47 起，DSH Android 连续降级：正常模式启动 → 前端 30 秒无健康证据 → 救援模式 → 安全模式（安全模式会摘插件 + 重解包引擎）。

真凶（日志 00:47:52 铁证）：
```
[PluginManifest] 插件清单已更新: 摘掉 dsh-android-bundle，bundles 现为 35 项
[PluginManifest] 插件清单已更新: 摘掉 dsh-core-memory，bundles 现为 34 项
[PluginManifest] 插件清单已更新: 摘掉 dsh-preset-razor，bundles 现为 33 项
```
三个**内置** bundle（dsh-android-bundle / dsh-core-memory / dsh-preset-razor）被摘出 `dsh.profile.bundles` 后：
- `dsh-android-mobile` 客户端桥（住在 dsh-android-bundle 里）不再加载 → 页面永不调用 `bridge.onUiReady()`；
- 硬件健康检测靠这条证据，30 秒收不到 → 判「client 半坏」→ 逐级降级。
- 关键鉴别：web.log 里少了 `[dsh-android-mobile@2026-11-10-features] 插件已装配` 和 `[dsh-android-mobile] onUiReady: ...` 两行。页面其实是好的（能聊天），是被误判。

修法：把三个 bundle 加回 `~/.dsh/profiles/web/package.json` 的 `dsh.profile.bundles`（共 36 项），并确认 `node_modules/` 里三个 `link:` 软链在（指向 `~/.dsh/node_modules/<pkg>`）。然后 rescue 信箱 try-boot 验 `ready:true`，再 switch-back。

排查经验：
- 安全模式把插件挪到 `profiles/web/.safe-mode-plugins/`、配置改名成 `*.bak-<ts>`，**不删东西**；恢复时把它们搬回 + 覆盖 package.json/cordis.patch.yml 即可。
- 安全模式会摘掉 `link:` 内置插件软链，恢复时要自己 `ln -s` 回来。
- 另一个真实崩溃：`dsh-memory-sync@0.3.0` 的 `lib/notify.mjs` 在 Android 上 `spawn('notify-send')`，spawn 失败是**异步 error 事件**，没挂 `child.on('error')` → uncaught → 引擎 fatal 退出。已给它加 `child.on?.('error', () => {})`（插件重装会丢，重装后 grep 一下）。
- rescue 信箱：写 `~/.dsh/rescue-cmd.json`（id 单调递增），1~25 秒后读 `~/.dsh/rescue-result.json`；`data.ready==true` 才算成功。
