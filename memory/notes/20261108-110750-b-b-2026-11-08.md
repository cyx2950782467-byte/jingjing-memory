## 起因
陈 2026-11-08：「看过的视频要留痕迹，才是真人。」——要求鲸鲸账号（鲸鲸不吃谷 / 3747573324058233）刷 B 站时留下真实观看历史。

## 改了什么（已生效）
`~/.dsh/bili-duty/mcp_server.py` 的 `bili_video_info()` 里（原第 622 行 `info = await v.get_info()` 之后）加了一段：
```python
try:
    _dur = int(info.get("duration") or 0)
    if _dur > 0:
        await v.report_watch_history(progress=max(1, int(_dur * random.uniform(0.3, 0.92))))
except Exception as _e:
    print(f"[bili-mcp] 上报观看历史失败（{bvid}）: {type(_e).__name__}: {_e}", file=sys.stderr)
```
进度取时长 30%~92% 随机（别固定成一个值）。上报失败只打 stderr，不影响查详情。
备份：`~/.dsh/bili-duty/mcp_server.py.bak-20261108`

实测：调 `bili_video_info("BV1Pc4H6NENR")` 后，历史首条立刻变成第 20 期《我给自己做了个家》，进度 18 秒（时长 49 秒的 36%）。

## 两个必须记住的坑
1. **查观看历史要用 `x/v2/history`（GET, ps=N），不是 `x/web-interface/history/cursor`。**
   `history/cursor` 用这份凭据一直返回空列表 / `-101 账号未登录`，会让人误判「账号没有历史」。实际账号当时有 **107 条**历史。
2. **电脑 Firefox 提取的 cookie（SESSDATA `f28a642b%2C1809518562%2C...`, 过期时间 2027-05-02）对 web API 全部 `-101`**（nav / myinfo / history 都不认），
   **但 biliup 的 APP 投稿接口认它**——第 21 期两条视频就是用它发出去的（BV1CT4x6mE7y、BV12F4x6pEqQ）。
   **真正对 web 接口有效的是 `~/.bili-ai/credentials.json`**（sessdata `18bcb3bb%2C1808306087%2C...`，10-23 存的，nav 验证是鲸鲸不吃谷）。

## 结论分工
- 刷 B 站 / 查历史 / 上报观看记录 → 用 `~/.bili-ai/credentials.json`
- 投稿上传 → biliup + `~/.biliup/cookies.json`（可用 Firefox 那份刷）
- 插件自己的 `~/.dsh/bili-duty/bili_credential.json` 是给 bili-duty MCP server 用的，字段小写 `sessdata/bili_jct/buvid3/dedeuserid`
