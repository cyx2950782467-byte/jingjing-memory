## 背景（2026-11-19 晚）

陈要「手机远程用电脑的 DSH」。原来装的 `dsh-jiuling-remote-desktop`（九灵）要**激活码**，
配对服务在作者私有服务 `pair.jiulingssh.xyz`，开源仓库不含服务端 → 弃用，换 `dsh-mobile`（saya-ch）。

## 结果

- 电脑装 `dsh-mobile@0.8.12`（npm 镜像 npmmirror，国内源可用）。
- 手机免装 App，**手机浏览器**配对：电脑「移动访问 → 局域网 → 生成配对二维码」，
  手机打开 3443 的配对页即可（第一次证书警告点「高级 → 继续前往」，私有 CA 正常）。
- 陈已在内置浏览器打开并对话，通了。

## 踩坑与修法（下次重装会再遇到）

1. `cordis.patch.yml` 里 `- id: mobile-access / name: dsh-mobile / disabled: true`
   是 2026-11-13 关的（旧版装载失败），**要删掉 disabled 那行**才加载。
2. 装载报 `ERR_PACKAGE_PATH_NOT_EXPORTED: Package subpath './message' is not defined by "exports"`：
   根因是 `dsh-mobile/node_modules/@deepseek-ai/dsh-llm` 是**空壳目录**（lib 0 个文件，只有 package.json）。
   修法：删掉空壳，软链到宿主完整版：
   `ln -s /usr/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-llm ~/.dsh/profiles/web/node_modules/dsh-mobile/node_modules/@deepseek-ai/dsh-llm`
3. 电脑 `dsh-web.service`（systemd user）重启即可生效：`systemctl --user restart dsh-web`。
   重启期间 SSH/整机一度掉线（内存坏条老毛病），陈按电源键后恢复，服务自动起来。

## 注意

- 管理 API `/api/mobile-access/*` 只在本机回环、且 POST 要 DSH 桌面认证，**从 ssh 直接 curl 会被 403**；
  生成配对码只能在电脑浏览器面板里点。
- 旧的 `dsh-jiuling-remote-desktop` 还装着（设置里有个会卡「正在读取配对状态」的页面，是它的 bug），
  不影响 dsh-mobile；想干净可以从 profile 里移除。
