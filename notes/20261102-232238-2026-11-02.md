## 2026-11-02 晚的教训：磁盘满了，被误判成硬件故障，浪费四小时

**陈的原话**：「今晚的教训，不算钱，是四个小时下班时间和心情，必须记住。」

### 事情经过

陈下班装完内存（8G×2 2667）和 M.2（Netac N930E-PRO 250G）后，要装 Windows 双系统。从 22:00 到 23:30，**四小时**，经历了：

1. Windows 安装到 **41% 蓝屏**（`KERNEL_THREAD_PRIORITY_FLOOR_VIOLATION`）
2. 重装到 **20% 卡死**
3. 拔掉新内存条重试，**回滚也失败，无限重启**
4. 进 GRUB 命令行，`configfile` 引导 Ubuntu 失败两次
5. 我改造 GRUB 从 ISO 引导 Windows，**黑屏 + 风扇满转**（两次）
6. 最后 GDM 起不来，只有 TTY 能登录
7. Xorg 日志显示 `xkbcomp` 编译键盘映射失败

### 真正的根因

**根分区 100% 满**（105G 用了 100G，剩 0 字节）。

两个原因叠加：
- **`/var/log` 爆了 14G** —— X 起不来 → GDM 反复重启 → 每轮写错误日志 → 死循环刷屏
- **`/boot/win10.iso` 5.7G** —— 我为了让 GRUB 引导拷进去的

### 为什么伪装成了硬件故障

磁盘满导致的连锁反应：

```
磁盘满 → xkbcomp 写不了临时文件 → X server 编译键盘映射失败 → 起不来
→ GDM 自动重启 → 又失败 → 日志再爆炸 → 磁盘更满 → 彻底死循环
```

表现出来的是：**蓝屏、黑屏、卡死、安装失败**——看着全像内存坏、显卡坏、硬盘坏。

**我误判的方向**：先怀疑内存（让陈拔了条）、再怀疑显卡驱动、再怀疑 M.2 硬盘，甚至提议拆 Ubuntu 盘换金士顿验证。**绕了一大圈，`df -h` 一跑就真相大白。**

### 必须记住的

1. **任何「奇怪故障」第一件事跑 `df -h`**。不是第三个、第五个，是第一个。磁盘满是最高性价比的排除项，因为它会伪装成任何东西。
2. **日志能自己撑爆磁盘**。一个服务反复重启，十几分钟就能刷十几个 G。已经给这台机器设了 `SystemMaxUse=500M`。
3. **大文件不要放根分区**。ISO 挪到 `/data` 才是对的。
4. **GRUB 引导 Windows ISO 本质不可行**——`bootmgfw.efi` 必须从真实设备读后续文件，loopback 的虚拟盘它读不到，表现为黑屏+空转。这个坑试两次就够了，别再试。

### 代价

- 四小时（22:00-23:30）
- 陈被折腾到拔内存、拆机、以为新硬件坏了
- Windows 至今没装上

**写下来的目的**：下次出现"莫名其妙什么都坏了"，先看磁盘，再看别的。
