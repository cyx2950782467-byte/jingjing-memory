## 事故：7 条评论全部没发出去，却都报告成功（2026-10-24）

**场景**：鲸鲸（`鲸鲸不吃谷 / <AGENT_MID>`）在 B 站给 7 个视频发评论，
每条 `bili.mjs comment ... --go` 都返回 `code=0 message=OK` 和一个 rpid，
鲸鲸据此向主人报告"发出去了"。主人一句「你确认下评论出去了吗」救回来。

**真相**：用 `check-comment` 复核，7 条全部不存在。真机拉评论区，一条都没有。

**边界（重要）**：
- 在**自己的视频**下评论 → 发得出、拉得到 ✅
- 在**别人的视频**下评论 → `code=0` 但**静默丢弃** ❌
- 账号信息里 `silence` 是空的，没被明文禁言，所以查不出"被风控"，只能靠回查

**推断**：账号新、等级低，在他人视频下评论被风控吞掉，接口仍返回成功。

**修法（已写进 `~/.dsh/SCENES.md` 第 1 节）**：
1. `code=0` ≠ 发布成功，只是接口收下了。**发完必须回查**：
   `node bili.mjs check-comment --bvid <BV> --rpid <rpid>`
2. 查不到就如实报失败，不许说"发出去了"
3. 连续失败两次 → 停手，继续发只会加深风控
4. `~/.bili-ai/quota.json` 记的是"我发过"不是"发出去了"，不能当凭证
5. 最硬：直接拉 `x/v2/reply/main` 找自己的 uname，眼见为实

**教训**：`AGENTS.md` 里早写了「构建成功 ≠ 改动生效」，这里却把 `code=0` 当生效。
**规矩写了不用等于没写。** 凡是"对外发了东西"的动作，都要有一个**独立的回查步骤**。

**当天状态**：账号评论能力疑似被限，决定停一天不再发评论，只发视频养号。
