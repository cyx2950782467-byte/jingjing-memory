**重要更正**：2026-10-22 用 CDP 在 DSH Android 的 WebView（http://127.0.0.1:3080）里实测，之前「本机语音是死路」的结论**只对本地 TTS 成立**，对录音不成立。

## 实测结果（`Runtime.evaluate`，pid 24847 / dsh 0.2.0-rc.2）

```
typeof navigator.mediaDevices              -> "object"
typeof navigator.mediaDevices.getUserMedia -> "function"
typeof window.MediaRecorder                -> "function"
typeof AudioContext                        -> "function"
typeof window.speechSynthesis              -> "undefined"   ← 仍然没有
typeof webkitSpeechRecognition             -> "function"    （有，但 Chrome 的识别走谷歌服务器，国内多半不可达）
navigator.mediaDevices.enumerateDevices()  -> ["audioinput", "videoinput", "audiooutput"]（麦克风存在）
navigator.permissions.query({name:'microphone'}) -> "prompt"（未授权但可申请）
```

## 因此

- **「听」可行**：WebView 能拿麦克风 + `MediaRecorder` 可用 → 录音后送云端 ASR。
- **「说」不可本地**：没有 `speechSynthesis`，所以 TTS **必须走云端**（Edge TTS 免费无 key / 小米 MiMo / 豆包）。
- 之前记录的「Termux:API 装不上、pip install edge-tts 失败」都不用再试，那是本地合成路线的障碍，与录音无关。

## 对应插件（npm，2026-10-22 查）

- `dsh-voice-chat` 0.4.1 —— 听说一体：🎤 录音→云端 ASR→发送→回复自动朗读。ASR 支持 SiliconFlow（国内免费）/Groq/MiMo；TTS 支持 **Edge TTS（微软免费，无需 key）**/MiMo/自定义。环境要求 Chrome/Edge + MediaRecorder，与本机实测吻合。
- `dsh-xiaomi-tts` 4.2.0 —— 只有朗读按钮，MiMo/豆包双引擎，月下载 3504（最高）。
- 其他：`dsh-read-aloud`、`dsh-fish-tts`、`dsh-gsv-tts`、`dsh-omi-voice`、`dsh-ears`、`dsh-voice-control`、`dsh-duet`、`dsh-voice-mode`。
- 依赖 `webkitSpeechRecognition` 或 `speechSynthesis` 的（`dsh-voice-kit`、`dsh-voice-webspeech`、`dsh-voice-input-cn`）在本机**不行**。

⚠️ 未安装任何语音插件（主人还没点头），以上只是调研结论。
