## 结论
「长会话就开新会话省 token」这条旧建议**是错的**，2026-11-16 实测推翻。

## 数据来源
`dsh-my-context` 插件落盘 `$DSH_HOME/context/context.json`（按会话分桶，每条 request 有
time(毫秒时间戳)/prompt/output/cacheRead/system/tools/user/inject/assistant/tool 字段）。
直接读这个文件就能自己算账，不用开面板。

## 2026-11-16 全天实测（167 次请求）
- prompt 累计 57,844,474，其中 **cacheRead 56,872,576 = KV 缓存命中 98.3%**
- output 仅 131,365
- 上下文构成：**assistant 51.5% ｜ tool 结果 18.9% ｜ tools schema 15.2% ｜ inject 13.7% ｜ user 0.7% ｜ system 0%**

## 三条结论
1. **人说的话只占 0.7%。** 「少说废话省 token」方向错了，99% 是机器为了对话而搬运的东西。
2. **换会话 = 把缓存全部作废**，下一轮统统按新价算。**省钱靠不换会话，省窗口才靠换会话**——两件事，别混。
3. **tools schema 每轮固定吃掉 15.2%**（100 多个工具的定义），跟聊什么无关。真要省，减工具比减字数有效一个数量级。
   assistant 占 51.5% 是滚雪球，工具调用该一次多带信息。

## 记住
以前在 handoff / AGENTS.md 里写过「任务超 10 轮就换会话省上下文」——**省钱的理由不成立**，
成立的理由只剩「窗口快满了」。以后别用省钱当换会话的借口。
