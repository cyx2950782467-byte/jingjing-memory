# 记忆生命周期管理（2026-11-22 学自 GPT，待落成 WS-MEM-001）

## 核心一句
压缩解决的是容量，不是可靠性。3.4KB 已经够了，下一阶段做「记忆可靠性」，不是继续压缩。

## 晋升判据（细节 → 常驻 MEMORY.md）
五维度各 0–2 分：复用范围 / 时间稳定性 / 判断影响 / 遗忘代价 / 使用频率。
- 8–10 分：晋升；5–7 分：留项目文件 + 索引；0–4 分：留档案。
- 三条限制：未验证的事实不晋升；有失效期的不用高分硬留；同一事实不存两份。
- 特殊标记 ANTI_REPEAT：踩过坑、容易再犯的（如「Kimi 网页发不出去」「内存坏重启要陈在场」），记错在哪 + 正确结论 + 复验条件。

## 防漏读（别靠自觉，做成前置门禁）
三道防线：
1. MEMORY.md 常驻读取规则（低强制）。
2. 每个项目一个 PROJECT_INDEX.md：状态/冻结架构/ADR/契约/环境/待办 + 该读什么。
3. Memory Read Receipt 门禁：任务分类 → 识别项目 → 读必需文件 → 记录实际读到的（含 sha256）→ 缺失则暂停报缺，不凭印象。
   高风险（改冻结架构/接口/部署/验收）必须走门禁；普通聊天不必。

## 生命周期：压缩 ≠ 降级 ≠ 归档 ≠ 删除
- 降级（常驻→按需）不丢；归档不丢；压缩丢细节；删除才真丢。顺序：降级 → 压缩 → 归档 → 删除。
- 六个触发：重复(合并) / 过时(更新+留历史) / 低频(降级候选，但不等于该删) / 范围缩小(归档) / 冲突(核实合并) / 注入收益低(降级)。
- 删除红线：用户明确长期约定、未解决的约束、决策原始证据、重大错误反例、未确认过时的事实——一律不自动删。
- 健康检查：事件驱动优先（阶段结束/环境变/ADR 被替代/验收失败立即更新），每周补一次。

## 三个反模式
1. 只拆文件，没有检索机制 → 假完整。
2. 同一事实多副本 → 一条事实只一个权威位置，其余只引用。
3. 项目「当前状态」与「历史」「冻结决策」混在一起 → 分 Current State / Frozen / Open / Milestones / Superseded 五块，Current 只一个权威版本。

## 六条制度（M-01..M-06）
M-01 新增长期记忆先判是否值得常驻｜M-02 项目任务先读项目索引｜M-03 改冻结架构读 ADR+契约（门禁）｜M-04 更新记忆查重复/冲突/过时｜M-05 普通压缩不删原始证据｜M-06 阶段转换更新项目当前状态。
