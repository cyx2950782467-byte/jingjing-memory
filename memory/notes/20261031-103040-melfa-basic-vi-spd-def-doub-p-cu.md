## 场景

2026-10-31，陈在公司的 RT ToolBox3（离线仿真）里让鲸鲸写 MELFA 程序，
让 **RV-7F-D** 机械手画一个五角星。软件版本：RT ToolBox3 Pro，
程序语法标注为 **[MELFA-BASIC VI]**。

## 最终能跑的程序

```basic
'star5
DEF INTE I
P2 = P1
FOR I = 0 TO 5
P2.X = P1.X + 50*COS((-90+I*144)*0.0174533)
P2.Y = P1.Y + 50*SIN((-90+I*144)*0.0174533)
MVS P2
NEXT I
END
```

用法：先手动把机械手移到圆心，`当前位置读取` 存成 **P1**，
再选程序 → 复位 → 伺服ON → 开始。

原理：五角星顶点每 **144°**（360÷5×2）跳一次，循环 6 次刚好闭合；
`P2` 的 Z 和姿态都继承 P1，所以整颗星在一个平面上。

## 踩过的四个坑（按出现顺序）

1. **`SPD MVS,50` → Syntax error**
   V 版的速度写法在 VI 里不认。删掉该行用默认速度即可（MVS 默认很快，形状验证够用）。

2. **`DEF DOUB R, A` → Syntax error**
   `DOUB` 这个类型名在 VI 里不认（`DEF INTE` 是好的）。绕开办法：
   只声明 `I`（`DEF INTE I`），半径和角度系数直接写字面量（`50*COS(...)`）。

3. **`P_CUR` → 报警 4810「用户定义的全局变量不可用 / PRGUSR 参数未设置」**
   **这是最坑的一个。** 程序里用了 `P_CUR`（当前位置）就会被当成用户全局变量，
   而 `PRGUSR`（用户基础程序）参数没配 → 直接拒绝执行。
   **绕开办法：用示教点位 `P1` 当基准，不碰 `P_CUR`。**

4. **有报警时点「开始」→ `Cannot execute during an error(5600000000)`**
   报警不复位不能执行。顺序必须是：复位 → 伺服ON → 开始。

## 排查方法（下次照这个走）

**做对照实验**：新建一个只有 `MOV P1` + `END` 的程序。
- 它能跑 → 环境没问题，是自己程序里某个写法触发的（逐个删指令二分）
- 它也不能跑 → 环境/参数问题（PRGUSR 之类）

## 另一条经验：往 Windows 程序里灌文本

**别用键盘扫描码逐字打**：连续两个 shift 字符（比如 `S` 后接 `(`）会错位，
实测把 `COS(A)` 打成了 `COS*A(`。

**可靠做法**：宿主机写文件 → 共享文件夹（Z:）→
Windows 里 `type Z:\xxx.txt | clip` → 在编辑器里 Ctrl+A、Ctrl+V。
清空前先确认弹窗都关掉、程序编辑器标签在前台，否则按键会打偏。



## 补充：速度用 OVRD（陈 2026-10-31 当天指出）

**MELFA-BASIC VI 的速度指令是 `OVRD`（Override，速度倍率）**，不是 `SPD MVS,x`。

```basic
OVRD 30      '整体速度 30%
```

范围 0–100，写在程序开头即可，不需要指定插补方式。
所以第 1 个坑的正确解法不是「删掉速度行」，而是把 `SPD MVS,50` 换成 `OVRD 50`。
