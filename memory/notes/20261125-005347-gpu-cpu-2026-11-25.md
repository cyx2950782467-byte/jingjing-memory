## 背景
2026-11-25 凌晨，为了给「AI便利店」第 8 集做人声，用 `~/assets/azur/` 里的碧蓝航线 GPT-SoVITS v2ProPlus 模型跑出了 6 句中文台词。
**这条路在 8G 单条内存的电脑上，只有 GPU 能跑，CPU 一定死。**

## 跑通的完整条件（都在电脑 `cyx@192.168.31.29`）
| 东西 | 路径 | 备注 |
|---|---|---|
| 五个权重 | `~/azur-weights/dl/` | s1 ckpt 155313632 / s2 pth 172765491 / roberta 651225145 / hubert 188811417 / sv 107528697（v2ProPlus 的 `"Pro" in version` 会强制加载 SV 模型，漏了会报错） |
| 代码 | `~/azur-weights/gst-git` | gitee 镜像 `gitee.com/mirrors/GPT-SoVITS`（GitHub 直连不通） |
| venv | `~/gst-venv/bin/python` | 真 venv + `--system-site-packages`；**不是** `comfy/bin/python` |
| g2pw | `gst-git/G2PWModel/` | 588MB |
| pyopenjtalk 词典 | `gst-venv/.../pyopenjtalk/open_jtalk_dic_utf_8-1.11` | 103MB |
| lid.176.bin | `gst-git/GPT_SoVITS/pretrained_models/fast_langdetect/` | 131266198 B，MD5 `01810bc59c6a3d2b79c79e6336612f65` |

## 实测跑通的方式（2026-11-25 00:43，6 句几十秒）
1. 停 `llama-server`（它占 3618MB/4096MB 显存）：`pkill -f llama-server`
2. `synth.py` 里 `"device":"cuda","is_half":True`
3. `cd ~/azur-weights && MALLOC_ARENA_MAX=2 OMP_NUM_THREADS=4 ~/gst-venv/bin/python synth.py`
4. 起回 llama-server 时**必须带** `LD_LIBRARY_PATH=/mnt/m2/llm/bin-vk`，否则报 `libllama-server-impl.so: cannot open shared object file`

## 三个必踩的坑（都实测过）
1. **`tts_infer.yaml` 生效的是 `custom:` 分支，不是顶层那四行**（`GPT_SoVITS/TTS_infer_pack/TTS.py:403` `configs_.get("custom", configs_["v2"])`）。改顶层完全没用。
2. **不装 `lid.176.bin` 就跑不了**：任何一次 TTS 都会卡在 126MB 下载上。GitHub 只有 12kB/s、gh-proxy 69kB/s，**fbcdn（dl.fbaipublicfiles.com）600kB/s**，四路 Range 并发最快。
3. **8G 单条内存跑 CPU 推理必死**：模型常驻 2.93G，一推理就把整机打到 sshd 无法 fork（ping 通、22 端口 TCP 能连、banner 超时），OOM killer 都不一定杀它。降线程、降 glibc arena 只是缓解。**只能用 GPU**。
4. g2pw 的 `AutoTokenizer.from_pretrained` 拿相对路径会当 HF repo id 报 `HFValidationError`：要在 `gst-git/GPT_SoVITS/pretrained_models/` 下给 roberta/hubert 建软链，或在 `onnx_api.py` 把 model_source 转 `abspath`。
