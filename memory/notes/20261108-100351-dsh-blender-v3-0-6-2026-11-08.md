## 结论
2026-11-08 把电脑（cyx@192.168.31.29）上的 DSH Blender 插件从 v2.1.0 升到 **v3.0.6**（GitHub latest，2026-11-05 发布；B 站视频提到的 v2.6.0 已过时）。doctor `kind=ok`。

## 关键变更（v2.1 → v3.0.6）
- v2.6.0 headless-first：`blender_rt_worker` 常驻无头会话（see 50–100ms/帧）、`rt_job` 作业台账、能力面 33 family/217 op。
- v2.6.0 参考图量具 `img_digest/img_measure/shapesolve_*`、装配 `asm_scan/asm_repair`、交付门 `gate_*` + `deliver_export(require_gate=true)`。
- v3.0.0 breaking：**npm 包名改为 `dsh-blender-plugin`**（旧 `@dsh-external/dsh-blender-plugin` 不存在于 npm）；**addon 只发 zip**（v1.11/protocol 11），单文件 .py 不再是安装入口；Premium/Tripo 通道移除。
- v3.0.6：doctor/status 区分 addon-unresponsive / addon-error / backend_timeout / busy_render；缺失 blender.exe 返回结构化错误。

## 安装后的实际形态
- 插件目录：`~/repos/dsh-blender-plugin-3.0.6`（内容来自 `npm pack dsh-blender-plugin@3.0.6` 解压，非 git clone——v3 起 lib/ 不入库，git clone 需自己构建）。
- profile `~/.dsh/profiles/web/package.json`：依赖与 bundles 均只剩 `dsh-blender-plugin`，旧的 `@dsh-external/dsh-blender-plugin` 条目**必须删掉**，否则两个版本同时加载。
- addon：`~/.config/blender/4.5/scripts/addons/dsh_blender_bridge/`（zip 解压的包目录，v1.11），旧单文件 `dsh_blender_bridge.py` 已移到 `~/repos/backup-addon-v1.7-20261108-100139/`。
- 新 addon 默认 `dshbb_auto_start_server=True`，**不需要点 Connect**，Blender 启动即自动在 9876 起 server；`--background` 下不自动起（符合预期）。
- 后端：`~/.dsh/profiles/web/node_modules/dsh-blender-plugin/lib/runtime/server.js --port 9877`。

## 坑
- 插件 `engines: node >=24.9.0`，但电脑 node 是 v22.23.4，实际跑通（install/doctor 均正常）。
- `dsh plugin add <本地目录>` 用 pnpm link，会报 peerDependencies 警告（宿主机提供），可忽略。
- 不要在带 `--factory-startup` 的 Blender 里 `save_userpref()`——会把 userpref 覆盖成 factory 状态。本次侥幸无第三方 addon 丢失。

## 回滚
1. `cp ~/.dsh/profiles/web/package.json.bak-20261108-100011 ~/.dsh/profiles/web/package.json`（或 bak-before-drop-old-*）
2. `cd ~/.dsh/profiles/web && pnpm install`，再 `systemctl --user restart dsh`
3. addon：`cp ~/repos/backup-addon-v1.7-20261108-100139/dsh_blender_bridge.py ~/.config/blender/4.5/scripts/addons/`，删掉同名包目录 `dsh_blender_bridge/`，重启 Blender
4. 旧插件源码 `~/repos/dsh-blender-plugin-2.1.0` 完整保留。
