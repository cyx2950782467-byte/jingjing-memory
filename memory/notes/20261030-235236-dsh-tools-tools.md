## 事故经过（2026-10-30 深夜，电脑上的 DSH）

想给电脑的 DSH 装个好玩插件（`@weibaohui/dsh-matrix`，黑客帝国数字雨），
`dsh plugin --profile web add` 之后 pnpm 干了两件事：

```
- @deepseek-ai/dsh-tools 0.2.1-rc.2
+ @deepseek-ai/dsh-tools 0.2.1-rc.5
- @linxin666/dsh-client-ui-task-board 0.4.5
- @linxin666/dsh-remote-web-ui 0.4.6
```

然后我误判方向：看到警告说「rc.5 与 dsh 0.2.0-rc.2 不兼容」，
就把 dsh-tools 锁成 0.2.1-rc.2 并重装 → **结果 tools 插件被整个禁用**：
`dsh: disabling profile plugin row "tools": dsh-tools@0.2.1-rc.2 is incompatible with dsh 0.2.1-rc.5`

## 根因（关键，别再搞错）

**`dsh --version` 显示的是 CLI 的版本（0.2.0-rc.2），不是实际运行时的版本。**

电脑上的服务是 `npx @deepseek-ai/dsh` 起的（不带版本号），
**实际运行时是 `0.2.1-rc.5`**。

所以 `dsh-tools` 必须跟 **运行时** 对齐（rc.5），不是跟 CLI 对齐。

**判定运行时的正确方法**：看启动日志里的 incompatible 消息，或者
`journalctl --user -u dsh | grep -oE "with dsh [0-9.]+-rc\.[0-9]+"`，
不要信 `dsh --version`。

## 修复步骤（已验证有效）

```bash
# 1. package.json 里把 dsh-tools 写成精确运行时版本
"@deepseek-ai/dsh-tools": "0.2.1-rc.5"

# 2. 重装
cd ~/.dsh/profiles/web && pnpm install

# 3. 重启
systemctl --user restart dsh

# 4. 验证（应该没有 disabling 输出）
journalctl --user -u dsh --since "-1min" | grep -iE "incompatible|disabling"
```

## 连带教训

- **装任何插件前先确认运行时版本**，别用 `dsh --version` 判断。
- `dsh plugin add` 会重算整棵依赖树，**可能顺手升级核心包、移除间接依赖**——
  装之前必须 `cp package.json package.json.bak-$(date +%m%d-%H%M)`。
- 这是同一类事故的**第二次**（第一次是 10-28，npx 自动升级）。
  **改电脑上的 DSH 等于动我的另一双手，要当成危险操作对待。**
- 想装好玩插件，`@dsh-external/*` 这批在 npmmirror 上多为 404（作者没同步镜像），
  能用的要单独确认：`@weibaohui/*`、`dsh-cost-meter`、`dsh-whale-musume` 实测存在。
