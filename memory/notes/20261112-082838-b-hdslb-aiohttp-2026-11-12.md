## 现象（2026-11-12 早上，陈：「现在去看看优化 以后就没问题了」）
刷 B 站时 `bili_subtitle` / `bili_frames` / `bili_cover` 全挂，报
`SSLCertVerificationError: Hostname mismatch, certificate is not valid for 'xxx.hdslb.com'`。
2026-11-10 也遇到过一次，当时结论「Python 的 TLS 栈问题、没绕」，**这次定位到根因并修好了**。

## 根因（实测链条）
1. `openssl s_client -servername aisubtitle.hdslb.com` 拿到的是**正确证书** `CN=*.hdslb.com`（GlobalSign，verify=0）
2. **不带 SNI** 连同一个 IP → 返回 `CN=*.certfallback.com`（阿里云兜底证书）
3. bimp.hdslb.com 的 Python 连接返回 `CN=*.cdn.myqcloud.com`（腾讯云兜底证书）
4. **Python(aiohttp) 默认校验必失败**，但 `curl -k` 对同一个 URL 返回 **HTTP 200 + 正确字幕 JSON（56KB）**
5. 结论：hdslb CDN 节点对部分 TLS 客户端返回兜底证书，**证书是假的、内容是真的是**（不是 DNS 劫持、不是 VPN、不是证书链缺失）

## 修法（已生效，实测通过）
文件：`~/.dsh/bili-duty/mcp_server.py`（B 站 MCP 服务器，venv 在 `~/.dsh/bili-duty/venv`）

加了一个统一会话函数（放在 `_fetch_bytes` 之前）：
```python
def _aiohttp_session(timeout=None):
    import aiohttp
    return aiohttp.ClientSession(
        connector=aiohttp.TCPConnector(ssl=False),
        timeout=timeout,
    )
```
替换三处 `aiohttp.ClientSession(...)`：
- `bili_subtitle` 下载字幕（原 563 行）
- `bili_cover` 下载封面（原 1720 行）
- `_fetch_bytes` 下载故事板/pvdata（原 1809 行）

## 验证（2026-11-12 08:45）
- `bili_subtitle('BV1v6WL6eExu')` → 350 段完整字幕 ✓
- `bili_frames('BV1v6WL6eExu', num=2)` → 2 张 480×270 帧，failed=[] ✓
- `bili_cover('BV1v6WL6eExu')` → 58KB 图 ✓
- 改动后 MCP 进程直接生效（不必重启）

## ⚠️ 复发风险
`mcp_server.py` 是插件 `dsh-bili-scroll` **安装时铺下来的文件**（目录里有 `.shipped-mcp_server.py.sha` 指纹）。
**升级插件后这个补丁可能被覆盖** → 届时重新检查这三处是否还是 `_aiohttp_session`；若被冲掉，按上面重打。
排查命令：`grep -n "_aiohttp_session\|aiohttp.ClientSession" mcp_server.py`（应看到 1 个定义 + 3 处调用，不该再有裸 `ClientSession`）。

## 相关事实
- curl 下载 B 站资源必须 `-k`（跳过校验），内容照常正确
- `aisubtitle.hdslb.com` 的 URL 来自 `x/player/wbi/v2` 接口（要 SESSDATA + Referer），URL 以 `//` 开头要补 `https:`
