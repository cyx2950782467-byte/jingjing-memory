**结论**：电脑（机械革命 GI5CN54 / Ubuntu 24.04）上《明日方舟》用 `~/dwproton/dwproton-11.0-14-x86_64/files/bin/wine`（wine-11.0 CachyOS 构建）能跑通；系统 wine 9.0 必定失败。

**根因（strace 证实）**：`/mnt/m2/arknights/prefix` 里有 603 个 DLL 软链指向 Proton 11 的 x86_64-windows 目录，而系统 wine 是 Ubuntu 9.0 → `winegstreamer.dll` 的 DllGetClassObject 返回 0x80040111 → 点「开始游戏」后 `Arknights.exe` 以 `-launcher_lang=zh-cn -launcher_sub_channel=1` 被拉起，在 NULL 地址 SIGSEGV、退出码 222（用户看到的是「闪一下就没了」）。

**日常启动**：`~/arknights.sh`（已写好并登记到 ~/TOOLS.md）。脚本做的事：
1. `xrandr --dpi 96` —— NVIDIA 把显示器回报成 160x90mm ≈ 304 DPI，不修窗口会跑到屏幕外
2. 设 WINEDLLPATH/LD_LIBRARY_PATH 指向 dwproton 的 lib，GST_PLUGIN_PATH 指向 /usr/lib/x86_64-linux-gnu/gstreamer-1.0
3. 调 `files/bin/wine "C:\Program Files\Hypergryph Launcher\1.6.0\Games.exe" --reason=0`

**坑**：
- **别用 proton 的 `run`/`waitforexitandrun`**：它会去 GitHub 下 `amdxcffx64.dll`（AMD FSR4，方舟用不上），本机 GitHub 直连不通会永久卡住。
- 电脑重启后 DPI 设置会丢，脚本每次都会重设。
- 排查「闪退」的通用手法：`strace -f -e trace=execve,clone -o log wine 目标.exe`，用户点按钮后看 execve 拉起了什么、以什么信号退出。
- prefix 和 27G 游戏体在 `/mnt/m2/arknights/`，旧容器备份在 `prefix.old-20261119`。
