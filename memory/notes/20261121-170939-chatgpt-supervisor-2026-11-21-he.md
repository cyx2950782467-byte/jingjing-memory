## 已验证的登录路径（可复用）
1. `browser` 工具打开 `https://chatgpt.com` → 未登录欢迎页。
2. `browser eval` 找 `button` 文本「登录」点它**没用**（弹窗没出来）；直接开 `https://chatgpt.com/auth/login` 更可靠。
3. 该页有 `input[name=username]`（占位「电子邮箱地址」）；`browser type` 填邮箱 → eval 点「继续」。
4. 会过 Cloudflare「请验证您是真人」→ 有时自动通过（本次约 10-20 秒后自动过了，页面跳到 `auth.openai.com/email-verification`）。
5. OpenAI 发**6 位邮箱验证码**；陈当时在手机上把码发给我（也可用 `shell` + Gmail app 截图读，但 Gmail 通知里没抓到码）。
6. `browser type` 填 `input[name=code]` → 点「继续」→ 登录成功，URL 回到 chatgpt.com。
- 已登录的会话历史在 `/c/<uuid>`；Supervisor 的线程名是「E3最终验收复审 (3)」等（`/c/6b014381-7a80-83ec-badc-603588d76d21`）。
- 页面**不是 canvas**：`data-message-author-role` 选择器拿不到 assistant 消息，读回复用 `document.body.innerText` 的尾部最稳。
- 输入框是 `div[contenteditable="true"]`，`browser type` 会报 Illegal invocation，必须用 `document.execCommand('insertText',false,text)`；发送点 `aria-label` 含「发送」的 button。

## 当晚技术发现（Whale Supervisor P3-C1/C1-E）
- **Worker 通道**：本机只有 `dsh --profile headless` 一次性进程可用；`dsh-sdk-jsonrpc-server` 代码在但 `~/.dsh/profiles/` 没有 sdk profile，启用=改 Profile（未授权）。
- **终态判定**：`--json` 流里 `{"type":"final","reason":{"kind":...}}` 是权威终态；**exit code 不可靠**——SIGTERM 打断长任务会 **exit 0 但没有 final、且报 `flush on a closed handle`（结果没落盘）**；SIGKILL 退 137、无 final。
- **无取消接口**：SDK 方法表无 cancel，headless 也无；取消只能进程级终止，副作用不可知（对应 cancelled / cancelled_unknown_effect / termination_failed 三分）。
- **session 单写者是真的跨进程**：同一 sessionId 第二个 headless 立即报 `already owned by an active write handle`，exit 1。
- **SIGTERM 后会话可恢复**：`--session-id` 续跑 turn 2 正常，但被打断那轮不可当成功。
- **headless 不读交互凭据库**：必须 launch-time 环境变量（如 `ZHIPU_API_KEY`），否则 `MISSING_CREDENTIAL` exit 1。
- **本机 headless 下 bash 工具不可用**：`workspace-write` 无 sandbox backend（缺 bubblewrap），工具拒绝执行且不派生进程；`tool_call`/`tool_result` 事件本身可用（带 callId）。
