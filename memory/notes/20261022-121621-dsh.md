2026-10-22 在 DSH Android（dsh 0.2.0-rc.2）上终于让自写客户端插件真正加载成功，之前失败五六次的原因是两个坑，**两个都满足才行**。

## 一、package.json 声明

必填：
```json
{
  "name": "dsh-deep-sea-theme",
  "type": "module",
  "main": "lib/index.js",
  "exports": {
    ".": { "default": "./lib/index.js" },
    "./client": { "default": "./lib/client.js" },
    "./package.json": "./package.json"
  },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": { "platform": "web" }
  }
}
```
- `dsh.client.platform` 必须是字符串（引擎源码 `@deepseek-ai/dsh-client-modules/lib/index.js:65` 校验）。`inject` / `external` / `immediately` 都是**可选**。
- 包必须真在 `$DSH_HOME/profiles/web/node_modules/<包名>`（pnpm install 会把不在依赖树里的目录移进 `node_modules/.ignored/`，所以手工放进去的包只要再跑一次 pnpm install 就会失效）。
- 包名必须出现在 `$DSH_HOME/profiles/web/package.json` 的 `dsh.profile.bundles` 数组里。

## 二、服务端半必须有 apply 函数（这是最容易漏的）

`lib/index.js` 只写 `export const name` + `export const inject` **不够**：
```
dsh: warning: 2 entries did not activate
dsh-deep-sea-theme (dsh-deep-sea-theme): failed to import
```
必须再加：
```js
export function apply(ctx) {
  ctx.effect(() => { /* ... */ return () => {}; }, 'label');
}
```
`node --input-type=module -e "import('包名')"` 能成功不代表引擎能激活——引擎要的是 apply。

## 三、客户端半的加载契约

`lib/client.js` 必须走模块加载器，不能直接操作 DOM：
```js
window.__ModuleLoader__.load({
  id: "包名",
  factory: () => ({ name: "包名", inject: [], apply(ctx) { ctx.effect(...) } })
});
```

## 四、怎么确认成功（不用瞎猜）

CDP 连 WebView 后读 `window.__DSH_BOOT__`：
- `entries` 里出现你的包名 = 引擎认它为 client 插件
- `batches[].url` 是 `/plugins/??<pkg>/client.js&rev=...` 这种组合 URL
- 注意：`/plugins/<pkg>/client.js` 这种单包路径是 **404**，别拿它测

引擎日志里搜包名，出现 `failed to import` 就是没激活。

## 五、CDP 连接的坑

- abstract socket `\0webview_devtools_remote_<pid>`，pid 用 **shell** 工具 `ps -A` 取（应用身份看不到别的进程），每次重启都变。
- `/json` 会列出多个 page，**必须先筛 `127.0.0.1:3080` 的主界面**，否则容易连到 `file://.../bubble-player/player.html`（悬浮球播放器，页面上啥也没有）。
- 脚本在工作区 `.tmp/petdiag.py`。
