## 结论（2026-11-14 深夜确诊）
陈的台式机（机械革命 GI5CN54）**内存有硬件读写错误**，不是怀疑：
- `memtester 2G 1` → **124 次 FAILURE**
- 当晚这次启动内核报 **10 次 MCE**；渲染时 Python 在 PIL 里段错误崩过
- 表现：高负载时整机卡死（连 ping 都不通），然后自己或被迫重启（11-15 00:05 停、00:11 回来）

## 陈明天要擦内存（金手指氧化），给他留的要点
- 断电、拔电源；手上先摸金属放静电
- 擦法优先级：纯棉布/眼镜布干擦 → 无水酒精（99% 异丙醇最佳；75% 医用酒精必须彻底干透）→ 牛皮纸/新钞票硬边轻磨
- **禁用**：砂纸、湿巾（含保湿剂）、带研磨颗粒的橡皮
- **一次只插一条**，跑 `memtester 2G 1`，过了再插第二条 → 定位哪条坏
- 两条都过 = 接触问题，擦干净即可；一条仍失败 = 换那条（DDR4 2667 8G 约 100–150 元）

## 坏内存期间我这边干活的规则
- 渲染**分块**跑，每块跑完校验帧（PIL 能打开 + `im.load()`），坏帧重渲
- 长任务一律 `nohup` + 日志，不指望一次成功
- 大文件传完做一次校验（大小/hash）
- 修好之前电脑随时会冻，别把关键进度只留在它上面

## 怎么验证好没好
