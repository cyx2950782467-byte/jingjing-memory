## 2026-10-23 实测：biliup 在 Android 上能跑，但登录过不去

### 能跑起来的部分（已验证）

`biliup` 有官方 **aarch64-android** 预编译包（28MB，v1.3.4，NDK r26d 构建）。
下载地址从 `https://api.github.com/repos/biliup/biliup/releases/latest` 的 assets 里找 `aarch64-android`。
解压后拿到 `biliupR-v1.3.4-aarch64-android/biliup`（61MB，ELF arm64），`chmod +x` 后直接能跑：

```
$ ./biliup --version
biliup-cli 1.3.4
```

命令齐全：`login / renew / upload / show / comments / reply / download / season / list`。
`upload` 参数足够用：`--title --desc --cover --tag --tid --copyright --submit`。

### 过不去的部分（登录）

**`biliup login` 需要真终端**，在无 tty 环境里报 `IO error: not a terminal`——它要在终端里画二维码。

**用网页 cookie 冒充 TV 凭证，无论多完整都 -400**。逐步试过：

1. 只给 `SESSDATA/bili_jct/buvid3` → 报 `missing field cookie_info`
2. 补 `cookie_info` → 报 `missing field token_info`
3. 补 `token_info` → `credential validation failed with Bilibili code -400`
4. 再加 `buvid4`（`x/frontend/finger/spi` 的 `b_4`）+ `bili_ticket`（`GenWebTicket`，需 hmac-sha256，key_id=ec02，key=XgwSnGZ1p）+ `DedeUserID` → 仍 -400
5. 真扫码登录成功后，把 ScanCookie（含 `sid`、`DedeUserID__ckMd5`）全并进去，九个字段齐全 → **仍 -400**

**结论**：biliup 要的是 TV 端 `access_token`，网页 cookie 再齐也过不了那关。

### 顺带验证的：网页版预上传接口也不行

`https://member.bilibili.com/x/vu/web/preupload` 无论带多完整的 cookie + 正确 referer，
一律返回 **404 HTML**（不是 JSON）。它只认网页端带特定 sign 的请求，光有 cookie 不够。

### 扫码登录本身是好用的

`https://passport.bilibili.com/x/passport-login/web/qrcode/generate` 拿链接，
`.../qrcode/poll?qrcode_key=<key>` 轮询：

- `86101` 未扫码 / `86090` 已扫未确认 / `0` 成功
- 成功后响应头 `Set-Cookie` 里有 `SESSDATA / bili_jct / DedeUserID / DedeUserID__ckMd5 / sid / default_sites`

**但要提醒主人**：扫码后出现的页面如果要求「短信验证码 + 手机号 + 身份证后六位」，
**那是钓鱼页，绝对不能填**。B 站登录从不问这些。

### 所以投稿怎么办

**继续用 App 手动上传**（一分钟的事）。别再为自动化投稿耗时间。

要真想自动化，只有两条路：
① 在 Termux 里跑 `biliup login`（有 tty，能画二维码），扫码拿 TV token
② 逆向 biliup 的 `-400` 到底要哪个字段

### 扫码的小技巧

二维码有效期很短（约 3 分钟），**扫完要立刻点「确认」**。
之前失败两次都是因为中间去查状态打断了节奏——**生成后不要中途轮询，让主人一次做完再说**。
