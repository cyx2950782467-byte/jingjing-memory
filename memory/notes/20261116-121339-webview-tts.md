## 问题
Android 上 DSH 里做实时语音对话：手机 WebView 里 `navigator.mediaDevices.getUserMedia({audio:true})` 直接返回
`NotAllowedError: Permission denied`。系统麦克风权限是开的（别的 App 能录音）。

## 四家模型圆桌结论（2026-11-16）
**共识**：
1. **不要在 WebView 里死磕录音**——真因是**宿主没实现 `WebChromeClient.onPermissionRequest`**，
   不是系统权限。所以 `pm grant`、Shizuku、adb 注入**全都救不了**。
2. **输出端（朗读）没有卡点**，卡点只在输入端。
3. **零成本首选**：系统输入法语音输入（讯飞/小米自带，按住空格说）+ 页面 `speechSynthesis` 朗读。

**待验证的两点（各花十分钟）**：
- DSH 这个 WebView 里 `window.speechSynthesis` 是否真能出声（部分定制 WebView 砍掉了它）
- 3080 有没有消息注入接口（若有，可做"手机录音→电脑 STT→注入会话"，彻底免手）

**其他路径（按代价升序）**：
- 输入法语音 + TTS 朗读（0 元，今天能通）
- Termux 侧装 STT 工具，录音走 Termux → 文本 → 本地 HTTP 信箱注入 DSH
- 电脑当网关：手机录音 → Tailscale 传电脑 → 电脑 STT → 回传注入

## 我的判断
先做第一条，把"能说话给它听、能听到它说"变成日常；第二条只在"不想碰键盘"时才值。
