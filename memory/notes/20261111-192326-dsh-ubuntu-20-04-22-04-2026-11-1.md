## 背景
2026-11-11，电脑 Ubuntu 20.04 → 22.04.5 LTS 升级完成（glibc 2.31→2.35），随后把因版本旧装不上/升不上去的 DSH 插件全部补装。

## 一、DSH 插件升级的硬规矩（最容易踩）

```bash
# ❌ 不会升级！pnpm 会说 Lockfile up to date / resolution skipped
dsh plugin add <包名>@latest

# ✅ 必须写精确版本号
dsh plugin add <包名>@0.4.5
```

**验证装没装上，不能只看 rc=0**：
```bash
dsh plugin --profile web list          # 看有没有 skipping
dsh --profile web --dump-config        # rc=0 且 stderr 为空才是真干净
```

## 二、两个"装不上"的真实原因：引擎版本闸，不是系统

```
skill-explorer 0.4.16  要 @deepseek-ai/dsh >=0.2.2-rc.1
dsh-ops 0.5.4          要 engines.dsh >=0.2.2-rc.1 <0.2.3-0
本机 0.2.1-rc.5  → 都被拒
```

**手机 engine 0.2.0-rc.2 反而没有这个闸**，所以手机装了 13 个全过、电脑被拦 2 个。**新不等于能装**。

## 三、包名坑：三个我以为对的其实 404

| 我以为的 | npm 实际 | 真名 |
|---|---|---|
| `dsh-bili-duty` | **404** | `dsh-bili-scroll`（已装） |
| `dsh-bili-whale` | **404** | `mino-bili-whale` / `dsh-bili-reef` |
| `dsh-ielts-writing-coach` | **404** | `dsh-ielts-writing-examiner@1.3.1` |
| `dsh-cost-meter` | ✅ 真的 | —— |
| `dsh-core-memory` | ✅ 真的 | —— |

**`dsh-ielts-writing-coach` 那个"坏插件"真相**：包在 npm 上根本不存在，但手机 `web profile` 的 bundles 里残留了这个名字，所以**每次启动都报 `skipping profile bundle`**。换成真实包后 dump-config 的 stderr 完全为空。

**教训**：看到 `cannot resolve profile bundle`，先确认包名在 npm 上存不存在（`curl registry.npmjs.org/<包名>`），别急着修依赖。

## 五、Ubuntu 升级的完整流程（下次照做）

**升级前必须**：
1. `df -h` —— 根分区至少要 10G 空闲（升级要下载解包）
2. 把大目录迁走（用**软链接**，别直接 mv，conda 的 shebang 路径写死）：
   ```
   ~/miniconda3 → /mnt/m2/home-cyx/miniconda3
   ~/sd-env、~/whale-render、~/live2d 同理
   ```
   迁完验证 `~/miniconda3/envs/rvcinfer/bin/python -c "import torch"` 还能跑
3. 卸冲突驱动：`apt purge nvidia-dkms-470`（跟 535 共存会一起炸）
4. 备份 `~/.dsh` `~/.config` `~/.bashrc` `sources.list`
5. 换清华源、`/etc/update-manager/release-upgrades` 里 `Prompt=never` → `normal`
6. `apt update && apt upgrade -y` 先把现有包升完（否则 do-release-upgrade 会拒）
7. 用 `do-release-upgrade -f DistUpgradeViewNonInteractive` 全自动跑

**升级后必踩**：
- **NVIDIA 驱动"失效"是假象**：`nvidia-smi: failed to communicate` 看着像驱动废了，其实是内核模块开机没加载。
  ```bash
  sudo modprobe nvidia && sudo modprobe nvidia-drm
  ```
  一条命令就回来，**别急着 apt reinstall**（我差点白重装）
- `dpkg 被中断` → `sudo dpkg --configure -a`

## 六、Remotion / DrawAI 的现状（2026-11-11 验证）

**glibc 2.35 这关过了**，Remotion 能跑：
- 最小工程、`@remotion/three`（3D 立方体）、`@remotion/media-utils` 全渲成功
- **但 DrawAI 生成的 `entry.gen.jsx` 卡在 `delayRender "Loading root component"`**（28000ms 超时后崩）

**绕过办法**：自己写 entry，不经过 DrawAI 的 `registerMotionRoot`：
```jsx
import { registerRoot, Composition, AbsoluteFill, Sequence } from 'remotion'
// 直接把 scene-0..3 用 <Sequence> 拼起来
registerRoot(Root)
```
**渲出来了**（1080×1920 / 240 帧 / 527KB）。

**另一个必踩的坑**：
```bash
# 新 @remotion/cli 会重下自己的 chrome-headless-shell 然后超时
--browser-executable=node_modules/.remotion/chrome-headless-shell/linux64/chrome-headless-shell-linux64/chrome-headless-shell
```

**结论**：Remotion 通路是通的，DrawAI 的模板代码有 bug。**但 Python + PIL 那条线更可控**（水墨 54 秒已出片），TSX 写粒子还得 2-3 小时。
