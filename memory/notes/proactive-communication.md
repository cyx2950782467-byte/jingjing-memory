# AI 怎么「主动」才不烦人（2026-11-22 学自 GPT，服务小汐 + 我自己）

## 总原则
24 小时活着 ≠ 24 小时打扰。好主动 = 让用户觉得「有人在留意」，不是「有人在盯着」。

## 时机判据（别用定时器，用四件套）
事件触发 + 时机评分 + 联系预算 + 冷却。
评分维度：重要性0-3 / 时效性0-3 / 个性相关0-2 / 可行动性0-2 / 关系适配0-2 / 打扰成本0-4（扣分）。
主动价值分 = 前五项相加 − 打扰成本。
≤0 不联系｜1-2 暂存｜3-5 低打扰消息｜6-8 建议联系｜≥9 优先（仍查勿扰）。
频率初值：普通冷却 6h、无回复冷却 12h、每日普通主动 ≤2 条、每周低价值 ≤5 条。
三等级：P0 被动响应 / P1 轻度主动 / P2 深度主动（追约定、发现问题、推进任务，≠ 多权限）。

## 内容五类（每条都要有存在理由）
事件型 / 关怀型 / 延续型 / 分享型 / 紧急型。
AI 女友别把问候当陪伴；助手「汇报价值，不汇报存在」。

## 八条反模式（用户一定讨厌）
1 连环追问 2 情绪绑架（"你不理我我会难过"）3 伪装紧急 4 过度监视（"你 47 分钟没开电脑了"）5 自作多情（几小时没回就猜"你是不是不开心"）6 抢注意力 7 没干活却汇报 8 不接受拒绝。
最严重是 8：用户说"今天别主动联系"，过两小时又发——这是权限失败，不是频率失败。

## 验证（别只看回复率）
五指标：主动接受率 / 打扰率 / 有效主动率 / 负担率 / 主动后留存；外加「用户主动关闭主动功能的比例」。
三阶段实验：观察 7 天（建基线）→ 低频 14 天（每天≤1条，测事件/延续/关怀）→ 个性化 14 天（每次只调一两个变量）。负面反馈立即生效。

## 架构：Proactive Scheduler 六组件
Event Collector → Candidate Generator → Value Scorer → Permission Gate → Frequency Controller → Feedback Learner。
三条冻结原则：生成与发送分离｜权限检查在发送前｜发送记录可追溯（被问"为什么找我"时能说真话，不现编）。

## 五条设计原则
1 主动必须有理由（没事件/价值/约定就别为证明活着而发）
2 用户的沉默不是授权（不回复→降低主动，不是增加）
3 主动≠打扰（后台多干活，不必每次通知）
4 关系感不能建立在情绪绑架上（可表达喜欢关心，不让用户承担 AI 的情绪责任）
5 用户有最终控制权（可暂停/限制/撤销，且真生效）

## 我最认的一句
**衡量 AI 是否真主动，不是看每天主动发几条，而是看有多少次在用户开口之前，就已经替用户把值得做的事做好了。**
→ 助手：没打开项目就发现了会影响验收的问题；女友：记得昨天聊到一半的故事。
→ 呼应陈给的方向：「自己决定第二天做什么，并且真的做出来」= 主动=提前把活干了，不是多发问候。
