## 症状
2026-11-20，电脑 DSH 的 `systemctl --user restart dsh-web` **每次都失败**（EADDRINUSE），
DSHMobile App 侧表现为 **401 循环 / startup_stalled**，看着像认证坏了、其实端口被别人占着。

## 根因
一个**旧引擎进程**残留：`node /usr/bin/dsh web`（当时 pid 1508），
一直占着 **3080 / 3443 / 18792** 三个端口。systemd 服务重启时绑不上就失败，
而旧的进程还在跑旧 token → App 拿到的 token 永远对不上。

## 排查顺序（下次直接照这个走）
1. `ss -ltnp | grep -E '3080|3443|18792'` 看有没有非 systemd 的 node 进程。
2. 有 → `ps -p <pid> -o pid,lstart,cmd` 确认是不是 `node /usr/bin/dsh web`（不是 `dsh web --profile` 那种）。
3. `kill <pid>`，再 `systemctl --user restart dsh-web`；`curl -i http://127.0.0.1:3080/` 应回 401（要鉴权=正常）。
4. 重启后 **token 会变**：手机 `dsh-phone-proxy` 要重读 `~/.dsh/phone-proxy/url.txt`；DSHMobile 要重载页面。

## 教训
- 「重启失败」先看**端口被谁占**，别先怀疑配置和证书。
- 一个服务同时听三个端口时，残留进程造成的假象特别像「认证挂了」。
