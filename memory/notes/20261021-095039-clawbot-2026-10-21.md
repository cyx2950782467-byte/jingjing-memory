## 背景
主人想把**手机上的 DSH（鲸鲸）接进微信**，用微信直接和她聊。他电脑上的 DSH 已经通过「微信 ClawBot / OpenClaw」做到了，所以拿着 ClawBot 的聊天截图问手机能不能也这么搞。

## 关键事实：ClawBot 是腾讯官方通道（不是第三方 hook）
- 官方名「微信 ClawBot 插件功能」，底层协议 **iLink**，接入域名 `ilinkai.weixin.qq.com`（腾讯官方服务器）
- 官方包：`@tencent-weixin/openclaw-weixin` / `-api` / `-cli`
- 开源桥接实现：`github.com/SkywalkerSpace/weixin-ClawBot-API`（Python `bot.py` / Node `bot.js`，兼容 Anthropic 格式 AI 接口，有扫码登录、长轮询、24 小时自动重连）
- ⚠️ **这条通道不怕封号**；普通的第三方微信 hook 才怕。两件事要分开判断。

## 手机端的真实障碍（2026-10-21 实测）
- DSH App 的 Web 服务只绑回环：`ss -ltnp` 显示 `127.0.0.1:3080`，局域网/外部都进不来
- 手机没有 CLI：`which dsh` 为空；`/data/user/0/com.dsh.android/files/engine/` 下只有 `node_modules`
- 但 `@deepseek-ai/dsh` 包**带 bin**（`lib/bin.js`），且有 `dsh-acp`（"Automation-only Agent Client Protocol server ... over JSON-RPC stdio"）——所以理论路径是：Termux 里装 dsh CLI → 跑 ACP → 写桥接
- 代价：Termux 里那个 dsh 和 App 里这只是**两个实例**，记忆不互通，除非共用 workspace 和日记

## 主人 2026-10-21 的决定
**选 C：先不接微信**。日常用 B 站私信 + 系统通知栏已经够。等某个周末他有空、人也在一整天，再一次性把完整方案（A）做扎实——**A 需要他在场扫码**。

## 备选（当时给过、没选）
B 方案：Termux 跑 bot.py 直接接 DeepSeek API + 把 AGENTS.md 人设当 system prompt。几十分钟能通，但**没有工具**（不会刷 B 站、不写日记、不记事），是"很像的假人"。

## 另一个已知坑（ClawBot 通道）
同一微信消息会被投递两次（senderId/chatId 完全相同、sentAt 差约 37 秒），第二次被当成新消息会掐断上一回合，形成「被掐断 → 重投 → 又掐断」死循环，最后报 `INTERNAL_UNKNOWN` 并"已解除与 OpenClaw 的连接"。要接的时候先解决重复投递。
