2026-11-18 下午（陈午睡时）两个子代理调研 + 我做的运镜层。

## 一、Blender 全自动角色：**整条不划算吃，但有三段零成本可吃**
来源视频 `BV1rysX6JEav`（作者「没有人比风堇更加可爱」，Opus 5.5 驱动，778s）。作者手法：
写规格文件 → build/render/check 三脚本 → 10 部件=10 个 py 模块 → 截面环放样建模 + 手指独立网格 →
赛璐璐（法线点积两色调 + 反壳描边）→ 11 轮盲选 80 PR 迭代到 10 万面 → MMD 956 骨骨架 + 最小二乘拟合权重 →
17 核心姿势 + 24 极端姿势逐帧断言 → 套 MMD 动作 + 150 刚体 Bullet 解算（穿模 8.3%→1.3%）→ 132BPM 切小节线，28 镜全切在拍上。

**三个判断**：
1. 它的**动作是借的**（sm29180863 モーショントレース），音乐也是借的——**没解决"动作从哪来"**
2. **2D 插画做 3D 会跑偏**：成片是标准 3D 动漫模型（有体积/透视/有厚度的后发），不是插画。要插画感应该走 2D 分层/纸片人
3. **成本差一个数量级**：1 角色 ≈ 880 次循环 + 12 并行子 agent；8 角色周更撑不起

**可吃三段**：① BPM→小节线→参数化机位（补我们缺的运镜层，我当天就做了）② 断言式质检（含"评审左右互换 14:1→平手"的偏见修正，自评要正反各看一次）③ 赛璐璐+反壳描边配方（将来做 3D 道具才用）

**验证状态（诚实）**：手机 `blender_status` = `available:false, spawn blender EACCES`（Android 没 Blender）；
电脑当时掉线 → bpy 那步**没跑过**。已真跑的只有纯 Python FK 预演（24 帧 0.25s，`~/.dsh/tmp/blender-lab/previs_fk.py`）。

## 二、dsh-better-ears 音频插件：**手机先不装**
- 兼容性其实没问题（`engines.node>=20`，零 dependencies，工具注册 API 逐字吻合 0.2.2）
- **但本地语音识别在 Android 上起不来**：`dshInstallCandidates()` 只认桌面路径；`sherpa-onnx-node` 没有 android-arm64 分支 → 等于只买到半副耳朵
- 唯一不可替代的是 `audio_rhythm`（BPM + 拍点网格 + 切点踩拍判定，容差 ±1.5 帧）；响度/静音/画面切点我们 ffmpeg 已有
- ⚠️ **npm 上 `dsh-better-ears` 是 404；`dsh-ears` 是别人的包，千万别 `npm i dsh-ears`**
- 等电脑回来装桌面版
